## Changes
- **Fix: spurious `devices` 403s right after sign-in.**
  `ensureDeviceRegistered()` (`device.store.ts`) fires as soon as the
  owner's `shops` row syncs on `SIGNED_IN`, but `devices` INSERT is
  owner-only server-side (`055_identity_domain_rls.sql`). That row syncs
  before the JWT's `active_role` claim is `'owner'` for a brand-new
  signup (bootstrap hasn't run yet) or a returning owner's fresh session
  on a device not yet PIN-confirmed this login — so the attempt always
  failed RLS with a 403, seen live in production as repeated `devices`
  403s immediately after sign-in. Fixed by decoding the JWT's
  `active_role` claim client-side (new `decodeActiveRoleClaim`, sibling
  to the existing `decodeSessionIdClaim`) and skipping registration
  unless it's `'owner'` — `refreshShopId()` already re-runs on every
  PowerSync reconnect, so registration retries automatically once
  `active_role` becomes `'owner'` (after bootstrap or an operator
  switch), with no extra plumbing needed.
