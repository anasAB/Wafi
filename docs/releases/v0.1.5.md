# v0.1.5 — 2026-07-30

**Git SHA:** `5f9672f`
**Migrations included (this release):** none — code-only release. Highest
applied migration at build time: 072.

## Changes
- **Fixed a `shopId` resolution race that skipped the login gate entirely.**
  `App.vue`'s `onMounted` only awaited PowerSync's generic first-sync
  checkpoint (`db.waitForFirstSync()`) before calling `hasAnyStaff()`, which
  filters by `device.shopId` — resolved independently by
  `device.store.ts`'s `refreshShopId()` (triggered off the `SIGNED_IN` auth
  event or a PowerSync reconnect), not by that checkpoint. On a cold start
  (full site-data clear + fresh login — confirmed live, 2026-07-29/30)
  `shopId` could still be at its empty fallback at that exact moment even
  though `shops`/`staff` had already synced locally, so `hasAnyStaff()`
  queried `WHERE shop_id = ''`, matched nothing, and — since this check
  runs once and is never retried — permanently misreported `hasStaff` as
  `false` for the whole session. That skipped `LockScreen` (the intended
  single gate: pick staff → PIN → open shift) entirely, leaving every
  gated route bounce through the router's redirect chain to
  `/shifts/history`, with the only apparent way back in being the sidebar's
  "switch user" action — which sets `sessionStore.activeStaff` but never
  opens a shift, which is why POS then stayed gated even after that
  workaround. Fixed by explicitly awaiting `refreshShopId()` before
  `hasAnyStaff()` (no extra round trip — it only reads the already-synced
  local `shops` table).
- **Fixed a real `ambiguous column name: created_at` SQLite error on the
  Reports page.** `useProfitTrend.ts`'s refund query reused the unqualified
  `bucketExpr('created_at', ...)` built for the single-table `sales` query
  inside a query joining `returns r JOIN sales s` — both of which have
  their own `created_at` column. Now uses the already-qualified
  `r.created_at` bucket expression, matching every other query in the
  file.

## Known issues
- The `vercel.com/sso-api` CORS error seen in the console is a Vercel
  Deployment Protection (SSO) setting on the raw `*.vercel.app` deployment
  URL, not an application bug — resolved via Vercel project settings
  (disable protection for this URL, or access the site via the real
  production domain instead).
- ADR-010's PowerSync sync-rule role-branching gap remains open (tracked
  separately as WAFI-201) and is unrelated to this release's fixes.
