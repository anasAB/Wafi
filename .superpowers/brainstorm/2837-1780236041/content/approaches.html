Epic 3 — Architecture approaches

How to structure the dashboard data layer and feature folders

A

Two feature folders (Recommended)

src/features/dashboard/ owns the aggregation composables (revenue, profit, best sellers, period toggle). src/features/expenses/ owns the expense form, composable, and types. HomePage.vue is rewritten to wire them together. Matches the established Epic 2 pattern exactly.

Pros

  • Clean separation — dashboard queries vs expense CRUD are distinct concerns
  • Each folder testable independently
  • Matches existing pattern

Cons

  • Two new folders to scaffold
B

Single dashboard feature folder

src/features/dashboard/ owns everything — aggregation composables, expense form component, and expense composable all live together. One folder, simpler navigation.

Pros

  • One place to look for all home-screen logic

Cons

  • Expense CRUD doesn't really belong to "dashboard" — it's a standalone feature that will grow (expense list, edit, delete)
  • Folder will get large
C

Extend existing HomePage inline

Don't create feature folders. Put all composables in src/composables/ and build everything inside the rewritten HomePage.vue. Faster to write, harder to test and maintain.

Pros

  • Minimal new structure

Cons

  • HomePage becomes a 600+ line god component
  • No clear boundaries for testing
  • Goes against established pattern

Click to select, then confirm in terminal. Recommendation is A.
